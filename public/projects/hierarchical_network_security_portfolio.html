Project write-up

I wanted my home lab to evolve from a mostly flat network into a hierarchical design with clearer security boundaries. Instead of treating every device as if it belongs on the same level of trust, I started organizing the environment around the core, distribution, and access layers.

At the core of the design, I am using OPNsense as the main firewall and routing platform to control how traffic moves between zones. From there, the distribution layer connects the environment through managed switching, and the access layer contains the actual endpoints, servers, monitoring systems, lab assets, and lower-trust devices.

This project has helped me strengthen my understanding of segmentation, defense in depth, redundancy planning, and least-privilege access. It also gives me a hands-on platform to keep refining firewall policy, test changes safely, and reduce the chance of unnecessary lateral movement across the network.

Next phase of improvement

  • Add redundancy at the distribution layer by introducing additional devices and pathways so the design becomes more resilient and scalable.
  • Further tighten rule sets to better align with least-privilege access rather than broad allow rules between zones.
  • Continue separating trust levels so user devices, server resources, lab systems, and IoT devices only reach what they actually need.

Least-privilege rule focus

Trusted endpoints → Server zone:Allow only required admin and management traffic such as SSH, HTTPS, or specific monitoring access.
IoT / Guest → Internal resources:Block access to sensitive internal systems by default; allow internet access only where appropriate.
Security lab → Production-style systems:Keep testing systems isolated and require explicit rules for any approved interaction.
Inter-zone access:Default deny, then add narrowly scoped exceptions based on service, source, destination, and business need.
